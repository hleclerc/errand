Tutorials ​

Four walkthroughs. Each one adds a leg, and each one is a directory you can cd into: the first three ship with errand, in examples/.

Which first? Start where your project is:

  • you want to see the layers (containers, ssh, Slurm) at work → 1 · Four environments
  • a pytest / Catch2 / cargo project → 2 · Adopt an existing suite
  • no framework, work to write with errand's own entries → 4 · errand's own entries
what it showsneeds
1 · Four environmentsenvironments as layer stacks, tags, building them, running in several at once, --batchreading, mostly
2 · Adopt an existing suitea pytest / Catch2 / cargo project, its tests run one by one, unmodifieda compiler, cargo
3 · Numbers over two machinesthe whole thing end to end: numbers taken in two places, comparedan ssh host
4 · errand's own entriesno configuration at all: entries, parameters, matrices, the output treenothing but errand

The second and the fourth need nothing but their own toolchain. Tutorials one and three name micromamba environments, Apptainer images, ssh hosts and a Slurm partition that do not exist on your machine — they are there to be read and adapted, and errand envs will tell you honestly that none of them is built.

Reading order, if you are in a hurry

Read Getting started. Then Environments and Where the output goes, which are the two ideas everything else is built on.
