# Caches dans la TUI et le web : décisions (2026-11-19)

- **Accès** : chaque run inscrit son `$ERRAND_CACHES` (tel qu'il le voit, avec sa vue) dans un registre de la machine (`~/.cache/errand/caches/<hash>.json`, comme `seen`) ; l'agent de machine répond aux ops `look` `caches` (résumé + entrées) et `caches_remove` (des clés, sous le verrou du compacteur). TUI et web passent par lui.
- **Répertoires partagés** : un id aléatoire écrit une fois dans le répertoire (`caches/errand-caches.id`) ; même id = même répertoire (bind de conteneur, NFS entre machines) : une ligne à l'écran, une suppression. Responsable : l'agent de machine (hôte) ; entre machines, la première qui l'a inscrit.
- **Binaires par vue** : à la bibliothèque de ranger ses binaires dans des répertoires appropriés (pas de `caches@<env>`).
- **Deps et vue** : errand donne `$ERRAND_CACHES_VIEW` (vide sur la machine nue, `<couche>:<image>` dans un conteneur/VM) ; la bibliothèque le recopie en champ `view` des lignes `create` (optionnel dans `errand-cache/1`) ; une purge ne juge les deps que des entrées de sa vue, et marque `dead` (date) celles qu'elle trouve mortes mais encore récentes ; l'écran lit les marques sans hacher.
- **Purge auto** : l'agent de machine, à son démarrage puis une fois par jour, sur les répertoires dont il est responsable (vue nue) ; un run dans un conteneur garde la sienne, limitée à sa vue ; un run nu n'en fait plus.
- **Écrans** : onglet caches (touche 3 en TUI, page web). Niveau 1 : (cache, machine) → entrées, taille, invalides, inutilisées depuis N jours. Niveau 2 : entrées fusionnées entre machines (clé, taille, dernier usage, invalide, présente sur…). Filtres invalides / inutilisées ≥ N jours (défaut 30) / toutes. `d` ici, `D` partout où la clé est (même clé, cache de même nom). Confirmation : nombre, taille, machines.
- **Partagées** : supprimer une partagée emmène les entrées qui en ont besoin (dit dans la confirmation) ; après une suppression à la main, les partagées que plus rien ne requiert partent tout de suite. Une entrée récemment utilisée part quand même.
- **CLI** : `errand caches [--env X] [--dry-run] [--unused DAYS]` ; pas de « partout » en CLI.
- **`errand caches --env X`** (interprétation, à confirmer) : tourne dans l'env X comme une commande de `errand run --env X`, donc dans sa vue : compacte, juge ses entrées, applique les règles (+ `--unused`), affiche.
