Runners ​

A runner is what runs a kind of file. errand.runners is a dict, name → runner, holding the ones below under the names in the first column, and a project edits it in errand-project.py — see Runners for how a file is given to one, and why the suites behave differently.

namerunnerleveltakesone entry per
errandErrand()ERRANDa .py that imports errandif test( … ):
pytestPytest()FRAMEWORKtest_*.py, *_test.pytest
catch2Catch2()FRAMEWORKtest_*.cpp that mentions catchtest case, after a build
cargoCargo()FRAMEWORKthe source root of a test target of the nearest Cargo.tomltarget
pythonPython()—a .py, named without ::file
executableExecutable()—anything else named without ::: an executable file, or a command on the place's PATHfile

The first four are entry runners, asked for a path::name target: the highest level wins, and a tie at the top is an error naming the runners, which -r NAME settles. The last two are file runners, asked for a target without ::; levels do not concern them.

python
errand.runners.replace( runner )            # in place of the runners of its kind; -> runner
errand.runners[ "bench" ] = runner          # beside them, under a name -r can pick
del errand.runners[ "cargo" ]               # and any other dict operation

Pytest ​

python
Pytest( dirs = None, patterns = ( "test_*.py", "*_test.py" ), args = ( ),
        python = None, install = "auto", spec = "pytest" )

One entry per test. Collection asks pytest itself rather than guessing: its rules are its own, and reimplementing them is how a runner starts quietly disagreeing with the tool it wraps. Nothing is built, so collecting is cheap.

dirsthe directories its files must be under, relative to the project root. Default: anywhere
patternsthe file names it takes
argsextra arguments passed to pytest
pythonthe interpreter to run pytest with. Default: the current one
install"auto" — install pytest when the environment is errand's to install into; True, False
specwhat to install, when it installs. "pytest", or a pinned spec

A @pytest.mark.slow is an entry tag, so -e '!slow' filters it with the same expression language that -t uses on environments.

install = "auto"

Into a venv, a micromamba environment or a container, a missing pytest is installed and errand says so. Into the system interpreter it declines and tells you what to run: that one is shared with everything else on the machine, and it is not errand's to change.

Catch2 ​

python
Catch2( dir = None, pattern = "test_*.cpp", build = None,
        binary = None, args = ( ) )

One entry per test case. build runs during the preparation, in the place the cases will run, and the binary is then asked for its cases ( --list-tests --reporter xml, or --list-test-names-only for Catch2 v2 ). A build that fails, or a binary that cannot list itself, costs its files' rows and nothing else.

A ::name in the target is handed to the binary as its own filter, so naming one case still reaches one case.

dirthe directory its sources must be under. Default: anywhere
patternwhich of them are suites. Default test_*.cpp
buildthe command you already build with. Runs once before any entry of this runner
binarywhere a source's executable lands. {stem} is the source's name, {dir} its directory. Default: beside it
{build_dir}in build and binary: this environment's own build directory, build/<env>/ ( errand.configure( build = … ) moves it ). The build also gets it as ERRAND_BUILD_DIR
argsextra arguments passed to the binary
python
# errand-project.py
errand.runners.replace( errand.Catch2( dir = "cpp", build = "make -C cpp" ) )
# or
errand.runners.replace( errand.Catch2( dir = "cpp", build = "cmake --build build", binary = "build/{stem}" ) )

build runs once before any entry of that runner, in the environment the entries run in — not once per file, and not once per parallel process, which under -j would have several of them writing the same binary at the same time. Leave it out entirely if something else already built them.

Cargo ​

python
Cargo( manifest = None, args = ( ), release = False )

One entry per test target; its file is the target's source root ( src/lib.rs, tests/foo.rs ), and its crate the nearest Cargo.toml above it, or manifest when given. cargo metadata knows the targets without compiling any of them, which is what makes collecting cheap. Naming a single test still works: the ::name part becomes the filter cargo test takes after --.

cargo test builds what it runs, so there is no build to declare.

Python, Executable ​

python
Python( )        # sys.executable of the place it runs in
Executable( )    # run as it is: a file of the project, or a command of the place

One entry each, the whole file or command, named after it; taken for a target without ::. A first word that names an interpreter ( python, python3 ) is the place's. A .sh is an executable like any other: it needs its execute bit and a shebang. Output is the run's output, the exit code the status ( 77 is a skip ), and ERRAND_OUT_DIR is set to the directory of the run when -o or --out asked for one.

Writing one ​

python
import errand
from errand import Level

class Mine( errand.Runner ):
    name           = "mine"
    level          = Level.FRAMEWORK   # the highest `suitability` can answer
    whole_files    = False             # True when an entry IS a whole file
    takes_selector = False             # ...and it hands a `::name` on to it

    def suitability( self, path ) -> Level: ...   # how well it fits this file
    def collect( self, specs ): ...               # -> the entries of the files it was given
    def prepare( self, entries, ctx ):            # once, before any of them. -> None, or why not
        return None
    def run( self, entry, ctx ) -> Outcome: ...

Registered with errand.runners[ "mine" ] = Mine( ), under which name -r mine picks it. level is what lets a walk over a whole tree ask only the runners that could make a file discoverable. A runner with builds_to_collect = True has prepare called before collect, during the preparation, with self.context.build_dir saying where the build goes. specs are ( files, name_glob ) pairs over the files this runner won; self.root is the project root, and self.entry( name =, file =, key = ) makes an entry of this runner's.

With whole_files = True, the ::name of a target belongs to the file rather than to the entry, so the core does not filter entries by it: with takes_selector = True it reaches run as ctx.selector, and without it is refused.

Building belongs in prepare, not in run: a suite is built once, not once per file, and -j would otherwise have several processes writing the same binary at the same time.

python
@dataclass
class Outcome:
    status : str                  # PASS | FAIL | SKIP
    error  : str | None = None
    results: dict = { }           # numbers; they land in result.yaml
    output : str = ""

RunContext carries the root, the out_dir this entry is writing into, its params, the env for the child, and the selector — the ::name part, when there was one.
