Where errand writes ​

errand writes in three kinds of places, on every machine it works on:

placewhatsize
the project: errand-outputs/ at its root ( over there, in the project's copy )every run's record, what was built, errand's bookkeepinggrows with use
per user: ~/.cache/errand/errand's own sources and, if needed, a Python for itself; sockets, locks and pids of what is runninga few MB, plus a Python if errand made one
per machine: a directory in $XDG_RUNTIME_DIR, else the temporary directorythe claims of machine sharinga few files

Then come the environments your layers build: a micromamba environment, a venv, a container image. They go where the declaration says, and each layer has a parameter to choose that.

Everything that grows belongs to a project, so you choose where it goes. The per-user directory holds only what is live, and cleans itself up ( see leaving nothing behind ).

The project: errand-outputs/ ​

text
errand-outputs/
  runs/       the record of every run
  builds/     what errand built: the Windows images, the records of what was set up
  state/      errand's bookkeeping: plans, history, the output kept for `errand attach`

What each holds is in Where the output goes.

Three settings move it, from the broadest to the most specific:

settingscopeexample
errand.configure( outputs_directory = … )the project, on every machine"errand-outputs" ( the default ), or "/data/me/proj-out"
ERRAND_OUTPUTS_DIRone machine: an environment variableexport ERRAND_OUTPUTS_DIR=/scratch/me/proj-out
Ssh( errand_outputs_directory = … )the project's copy on that host"/scratch/me/proj-out"

A relative path is from the project root. With errand_outputs_directory, the project's copy over there holds a symlink errand-outputs to the directory, so nothing else changes. What the copy's own errand-outputs/ already held is moved there at the next push. The two other settings move nothing: a run writes to the new place, and the old one stays as it was.

builds/ can go somewhere else on its own, with errand.configure( builds_directory = … ): another disk, or a directory several projects share, so that they share one Windows image. It is the same path on every machine, so an absolute path must exist on each of them.

Over Ssh: the project's copy ​

Ssh( root = … ) is where the project is copied over there. Without it, the copy goes to the same path as here: /home/me/proj here means /home/me/proj over there. On a cluster, that is usually the home directory, so you will want root to point at a work or scratch disk:

python
errand.Ssh( host = "cluster", root = "/scratch/me/proj" )

The copy holds everything that follows from it: errand-outputs/ ( unless errand_outputs_directory says otherwise ), a Uv venv, and a container image declared with a relative path.

The per-user directory: ~/.cache/errand/ ​

On a machine reached by Ssh, errand puts its sources here ( about 1 MB per checkout that asked ). If the machine has no usable Python, it also makes one here for itself, with uv and maybe the uv it fetched first. That is tens of MB, once. The rest is live: the directories of the agents and of the hub, a warm Slurm allocation, the virtual machines that are booted. These go away by themselves.

It is in the home directory on purpose: on a cluster, the home is what the login node and the compute nodes share, so what errand finds or makes on the login node is what a job uses on a node. There is no setting to move it. If your home really has no room, replace it by a symlink to a disk that the nodes also see:

bash
mv ~/.cache/errand /work/me/errand-cache    # or rm -rf it: errand remakes what it needs
ln -s /work/me/errand-cache ~/.cache/errand

Removing ~/.cache/errand is always safe when nothing is running: it undoes everything errand made for itself.

The tools' own caches ​

Some tools that errand runs keep caches of their own in the home directory: pip in ~/.cache/pip, uv in ~/.cache/uv, apptainer in ~/.apptainer/cache. errand leaves them alone. To move them, set their variables in your account's environment over there ( ~/.bashrc, say ):

bash
export PIP_CACHE_DIR=/scratch/me/cache/pip
export UV_CACHE_DIR=/scratch/me/cache/uv
export APPTAINER_CACHEDIR=/scratch/me/cache/apptainer

For apptainer builds, Apptainer( scratch = … ) does that for you.

A small home, in short ​

python
errand.Ssh( host = "cluster",
            root = "/scratch/me/proj",                         # the project's copy
            errand_outputs_directory = "/scratch/me/proj-out" ) # runs, builds, state
errand.Micromamba( "proj", root_prefix = "/scratch/me/mamba" )  # environments
errand.Apptainer( "proj.sif", recipe = "proj.def", scratch = "/scratch/me/tmp" )

Plus, if even a few MB are too many, the symlink for ~/.cache/errand, and the tools' cache variables.
